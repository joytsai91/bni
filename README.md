# BNI 分會管理系統

用 Google 試算表存資料、Google Apps Script 做網頁，不用租主機。每位幹部用自己的帳號登入，看到的功能依角色而定；手機、平板、電腦都能操作。

文件只有三份：本檔（索引與現況）、[WHITEPAPER.md](WHITEPAPER.md)（業務規則：為什麼這樣設計）、[WHITEPAPER_APPENDIX.md](WHITEPAPER_APPENDIX.md)（技術附錄：資料表欄位、權限代碼、API）。

## 部署（約 10 分鐘）

1. 建立一份 Google 試算表，例如「BNI 台中市中心區湧泉分會 管理」。
2. 試算表選單「擴充功能 → Apps Script」。
3. 把程式放進去，二選一：
   - **複製貼上（不用安裝任何工具）**：用打包好的 4 個檔案（`npm run bundle` 產生在 `dist/`，或向開發者索取），用記事本等文字編輯器打開、全選複製：
     1. `1-Code.gs.txt` → 編輯器裡原本的 `Code.gs`，內容全部刪掉再貼上。
     2. `2-appsscript.json.txt` → 先到「專案設定」勾選「在編輯器中顯示 appsscript.json 資訊清單檔案」，再把 `appsscript.json` 的內容換成這份。
     3. `3-App.html.txt` → 檔案旁的「＋ → HTML」，命名 `App`（不用打 .html），貼上。
     4. `4-Register.html.txt` → 同上，命名 `Register`，貼上。
     5. 按儲存。
   - **clasp（工程師、之後常更新時建議）**：`npm i -g @google/clasp` → `clasp login` → 把 `.clasp.json.example` 複製成 `.clasp.json`，填入 Apps Script「專案設定」裡的指令碼 ID → `clasp push`。
4. 回到試算表重新整理，選單會出現「BNI 分會工具」：
   - 「初始化資料表」：第一次會要求授權。Google 會顯示「這個應用程式未經 Google 驗證」，因為這是你自己的程式，按「進階 → 前往」繼續。
   - 「建立管理員帳號」：輸入登入帳號、顯示名稱、密碼（至少 8 碼）。第一個帳號只能從這裡建立。
5. Apps Script 編輯器「部署 → 新增部署 → 類型：網頁應用程式」：執行身分選「我」，存取權選「所有人」。用 Google Workspace（公司網域）帳號時，要選「所有人」而不是只限網域內，否則來賓打不開報名頁。
6. 試算表選單「顯示系統網址」取得管理系統與報名頁網址，用管理員帳號登入。
7. 到「系統設定」填分會名稱、例會星期與時間，並為其他幹部建立帳號、指定角色。

程式更新後，到「部署 → 管理部署」編輯既有部署並選「新版本」，網址就不會變。忘記密碼時，可從試算表選單「重設帳號密碼」。

**從前一版更新上來時**：放上新程式後，先在試算表選單再執行一次「初始化資料表」，再發布新版本。這一步會建立新的工作表（收支帳、會費紀錄、訊息範本、發送紀錄），也會讓 Google 要求新的授權（用你的 Gmail 寄信、連線到 LINE、建立排程）。沒有授權，寄信與 LINE 推播會失敗。

### LINE 機器人（要直接推播到群組才需要）

1. 到 [LINE Developers](https://developers.line.biz/) 建立 Messaging API channel（會同時建立 LINE 官方帳號）。
2. 「Messaging API」分頁最下方發行 Channel access token（long-lived），貼到系統「LINE 小助理 → 機器人設定」，系統會先向 LINE 驗證再儲存。
3. 把機器人設定頁顯示的 Webhook 網址貼到「Webhook URL」，開啟 Use webhook；在 LINE Official Account Manager 關閉「自動回應訊息」、允許「加入群組」。按 Verify 可能顯示錯誤（Google 會轉址），只要下一步綁定成功就沒問題。
4. 把官方帳號邀請進分會的 LINE 群組，在系統按「產生綁定碼」，10 分鐘內在群組輸入「綁定 六位數字」。
5. 要自動推播每週提醒：在機器人設定勾選「每週提醒自動推播」，並在「系統設定 → 每週提醒」勾選要推播的提醒。

**額度**：推播到群組時，群組裡每位成員都算一則。免費方案的每月則數有限，機器人設定與發送頁都可以查本月已用多少；只想省額度就用「複製」或「分享到 LINE」，不花額度。

## 角色與權限

每個帳號可以有多個角色；所有人都能看首頁與活動。權限代碼格式是「模組.資源.動作」，完整清單在 `src/Config.js` 的 `PERMISSIONS`。

| 角色 | 可以使用 |
| --- | --- |
| 系統管理員 | 全部功能 |
| 主席團 | 全部功能，但不能管理帳號 |
| 財務 | 財務中心；會員名冊、活動來賓只能看 |
| 會員委員會 | 評議與追蹤、產業分析、會員名冊、活動來賓 |
| 來賓接待 | 簽到與列印、活動來賓、來賓速覽、幸運轉盤、LINE 小助理 |

## 每週流程

- **例會前**：在「活動來賓」複製報名連結（或會員個人邀請連結）貼到 LINE，來賓填完就會出現在名單；「報名儀表板」看各場報名狀況；在「簽到與列印」印名牌、桌牌與簽到表。
- **例會中**：用平板開「簽到與列印」，會員到場點名字，來賓按「簽到」「已繳費」；臨時來的來賓按「＋ 現場來賓」。介紹來賓時開「來賓速覽」的投影模式；抽獎用「幸運轉盤」。
- **例會後**：按「未簽到者記缺席」，再按「出席結果文字」複製給秘書或貼到 LINE。到場的來賓已自動加入「評議與追蹤」，指派負責人與下次追蹤日；會員委員會用「產業分析」確認來賓是否撞行業。在「信件管理」選「感謝來賓蒞臨」範本、寄給「活動來賓（已簽到）」。
- **PALMS**：從 BNI Connect 匯出 PALMS 報表，在「PALMS 報表」上傳，確認期間後儲存，再按「LINE 週報」，或在「LINE 小助理」選「PALMS 週報」推播。
- **財務**：簽到時按「已繳費」的來賓費會自動入帳；月費在「財務中心 → 月費繳納」點格子收款；場地費、餐費等支出用「＋ 記支出」。每月看「月結」確認餘額。

## 資料表（都在同一份試算表）

| 工作表 | 說明 |
| --- | --- |
| 設定 | 分會設定，也可以在「系統設定」修改 |
| 帳號 | 帳號、顯示名稱、職稱、角色、狀態。**密碼不在這裡**，雜湊後存在 Apps Script 指令碼屬性 |
| 會員名單 | 會員ID 留空會自動補；狀態填「離會」「休會」「停權」就不會出現在簽到與列印；列印順序就是名單順序 |
| 活動 | 共識會議、培訓等活動；每週例會不用建，只有個別例會停會或改地點時才會在這裡多一列（活動ID 是「MTG-日期」） |
| 報名名單 | 報名頁、代為登記、現場報名都寫進這裡（每列有活動ID） |
| 會員出席 | 每場例會每位會員一列（P 出席、L 遲到、S 代理、M 病假、A 缺席） |
| 每週提醒 | 顯示在首頁「這一週」的固定提醒 |
| 抽獎紀錄 | 幸運轉盤每次抽中的人、獎項、操作人 |
| 追蹤名單 | 來賓追蹤：來訪次數、階段、負責人、下次追蹤日、最新進度 |
| 追蹤紀錄 | 每次聯繫與階段變更的紀錄 |
| 招募目標 | 分會想找的專業別與優先度 |
| 收支帳 | 每筆收入、支出一列；作廢只改狀態並記原因與作廢人，不刪列 |
| 會費紀錄 | 每位會員每個月一列；同一次繳的月份共用同一筆收支帳 |
| 訊息範本 | Email 與 LINE 範本；第一次建立時會放入 6 個常用範本 |
| 發送紀錄 | 每封信、每則 LINE 推播（含每週提醒自動推播）的結果 |
| PALMS | 每一期（起訖日期）一批資料 |

- 欄位依標題對應：在試算表裡調整欄位順序、在右邊加自己的欄位都沒關係，但不要改標題文字。
- **刪除一律是軟刪除**：有「已刪除」欄的表，刪除只會把這欄標成「是」，原始資料留在試算表。同一期 PALMS 重新匯入也是把舊資料標成已刪除。收支帳與會費紀錄不能刪除，只能作廢。
- 完整欄位、權限代碼與 API 清單在 [WHITEPAPER_APPENDIX.md](WHITEPAPER_APPENDIX.md)。

## 安全

- 每位幹部各自帳號。密碼加鹽雜湊後存在指令碼屬性，有試算表權限的人也看不到；同一帳號連續輸錯 5 次會鎖 15 分鐘。
- 登入後拿到 14 天有效的簽章憑證；改密碼、重設密碼、停用或刪除帳號，該帳號在所有裝置的登入立即失效。
- 每個 API 都在伺服器端檢查權限，不是只把按鈕藏起來；至少會保留一位啟用中的系統管理員。
- 報名頁是公開的：只能新增報名，只看得到會員姓名與專業別（邀請人選單用）；有防機器人欄位與送出次數上限；不接受編造的例會日期；不能自己標記已繳費。
- LINE Channel access token 只寫不讀，存在指令碼屬性。LINE Webhook 網址是公開的，Apps Script 拿不到 LINE 的簽章，所以綁定群組靠「系統產生、10 分鐘有效、用一次就失效」的綁定碼，猜錯太多次會暫停綁定；Webhook 也有次數上限。
- 寄信一次最多 100 封，寄出前檢查 Gmail 當日剩餘額度；改過內容必須重新預覽才能寄。
- 填寫的內容寫進試算表前會轉成純文字，不會被當成公式執行；顯示在畫面上時也會跳脫，不會被當成 HTML。
- Excel 解析用 SheetJS 官方 CDN 的 0.20.3（npm 上的 0.18.5 有已知漏洞，只在本機開發測試時使用）。

## 開發

```bash
npm install
npm test        # 核心邏輯與後端流程測試（用 dev/gas-fake.js 模擬 Google 試算表）
npm run dev     # 本機預覽 http://127.0.0.1:8080/exec（含示範資料，帳號密碼會印在終端機）
npm run e2e     # 用 Chromium 實際操作畫面，輸出截圖與列印 PDF 到 .e2e-output/
npm run bundle  # 產生複製貼上部署用的 4 個檔案到 dist/（改過程式要重新產生）
```

- `dev/gas-fake.js` 會模擬試算表的自動轉型：沒處理好的電話會掉開頭 0、日期字串會變日期、公式字串會直接報錯。寫入相關的程式改壞了，測試抓得到。
- 前端：`App.html` 是外框，`ShellJs.html` 負責登入、選單與換頁，每個功能是一個 `Page*.html`；共用工具在 `Common.html`。
- 後端：`Code.js` 是 API 入口（每條路由標註權限），`Auth.js` 帳號，`Events.js` 活動與報名儀表板，`Guests.js` 報名，`Attendance.js` 簽到，`Meeting.js` 來賓速覽與幸運轉盤，`Followups.js` 評議與追蹤，`Industry.js` 產業分析，`Members.js` 會員，`Finance.js` 財務，`Messages.js` 範本與寄信，`Line.js` LINE 機器人（Webhook `doPost`、每小時排程 `cronHourly`），`Palms.js` PALMS，`Home.js` 首頁，`Settings.js` 設定，`Lib.js` 純邏輯，`Db.js` 試算表存取。
- 本機預覽的 LINE 是假的：任何 20 碼以上的 Token 都算有效；產生綁定碼後用 `curl -X POST http://127.0.0.1:8080/__dev/line -d '綁定 123456'` 模擬在群組輸入。寄信只記在記憶體，不會真的寄出。
